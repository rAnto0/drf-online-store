# Обзор

Проект main-api представляет собой серверную реализацию API, которая обеспечивает работу различных модулей приложения. Весь код разделён на логические блоки для облегчения поддержки и расширения функциональности. Основное внимание уделяется структурированным настройкам, маршрутизации запросов, обработке данных и интеграции с фронтендом.

# Папка zaharovo

Папка **zaharovo** содержит основную конфигурацию приложения, в том числе настройки проекта, маршруты (urls) и возможно другие утилитарные файлы.

Ниже представлен обзор ключевых файлов в папке zaharovo, которые отвечают за конфигурацию и маршрутизацию проекта. Начнем с файла settings.py, затем перейдем к urls.py, обсудим интеграцию с yasg для документации, а также кратко коснемся файлов asgi.py и wsgi.py.

## 1. settings.py

Файл settings.py является центральной конфигурационной точкой приложения и содержит следующие основные настройки:

- **Базовая конфигурация проекта**:  
  Здесь задаются основные параметры, такие как BASE_DIR (базовая директория проекта), SECRET_KEY (секретный ключ для обеспечения безопасности) и DEBUG (режим отладки). Эти параметры управляют базовыми аспектами работы приложения.

- **INSTALLED_APPS**:  
  В этом разделе указываются все установленные приложения, как стандартные приложения Django (например, django.contrib.auth, django.contrib.admin и т.д.), так и сторонние библиотеки, включая Django REST Framework, yasg и другие. Аналогичным образом здесь добавляются все внутренние приложения проекта.

- **MIDDLEWARE**:  
  Список middleware-компонентов, которые обрабатывают запросы и ответы. Обычно здесь присутствуют стандартные middleware, такие как SecurityMiddleware, SessionMiddleware, CommonMiddleware и др. При необходимости могут быть добавлены пользовательские middleware для обработки CORS, логирования или авторизации.

- **Конфигурация базы данных**:  
  Определяются параметры подключения к базе данных (например, PostgreSQL, SQLite или другой СУБД). Задают имя базы, пользователя, пароль, хост и порт.

- **Настройки шаблонов (TEMPLATES)**:  
  Видео настройки для рендеринга HTML-шаблонов, указание каталогов для поиска шаблонов и использование контекстных процессоров для передачи служебных данных в шаблоны.

- **Конфигурация Django REST Framework**:  
  Здесь задаются настройки REST API: разрешения по умолчанию, классы аутентификации (например, JWT), пагинация, фильтрация и другие специфичные параметры для работы с API.

- **Логирование**:  
  При наличии – конфигурация для логгирования, позволяющая настраивать вывод сообщений для разработки и продакшена, в том числе разделение логов по уровням (DEBUG, INFO, WARNING, ERROR).

- **Настройки статических и медиа файлов**:  
  Определяются пути к статическим ресурсам (CSS, JS) и медиа файлам, что важно для развертывания проекта.

- **Дополнительные настройки**:  
  Могут присутствовать конфигурации для работы с внешними сервисами, настройки кэширования, параметры для загрузки файлов и прочее.

Все эти настройки объединяются для того, чтобы приложение работало корректно, имело безопасное окружение и поддерживало хорошую масштабируемость.

## 2. urls.py

Файл urls.py в папке zaharovo отвечает за маршрутизацию входящих HTTP-запросов. Основные моменты:

- **Импорт и подключение маршрутов**:  
  На верхнем уровне импортируются функции и классы из Django для работы с URL-паттернами. Кроме стандартных маршрутов (например, административной панели `/admin/`), происходит включение маршрутов из различных модулей проекта (например, API, аутентификации, продуктов).

- **Подключение API маршрутов**:  
  Часто файл urls.py объединяет маршруты из внутренних приложений через функцию `include()`. Например, для API может быть прописано что-то вроде:  
  `path('api/', include('app_name.api_urls'))`  
  Таким образом маршруты структурированы и легко модифицируются.

- **Маршрутизация документации**:  
  Если в проекте используется модуль для документирования API (например, yasg), может быть определен отдельный URL для Swagger-документации, например:  
  `path('swagger/', schema_view.with_ui('swagger', cache_timeout=0), name='schema-swagger-ui')`

- **Использование регулярных выражений и namespace**:  
  При необходимости могут быть заданы паттерны для динамической маршрутизации и определение неймспейсов для разделения логики разных блоков маршрутов.

Таким образом, urls.py служит навигатором для всех маршрутов, определяя, какое приложение и какой модуль должен обрабатывать конкретный запрос.

## 3. yasg

yasg (Yet Another Swagger Generator) – это инструмент для автоматической генерации документации API на основе схемы, определенной в Django REST Framework. В моем проекте интеграция yasg реализована следующим образом:

- **Создание schema_view**:  
  В файле urls.py или в отдельном модуле создается объект schema_view, с использованием метода `get_schema_view` из библиотеки drf-yasg. Этот объект включает в себя описание API, информацию о лицензии, версии, заголовках и другие метаданные.

- **Настройка документации**:  
  schema_view настраивается так, чтобы обеспечивать два варианта отображения: Swagger UI для визуальной документации и Redoc для альтернативного представления. Например, можно прописать следующие маршруты:  
  ```
  path('swagger/', schema_view.with_ui('swagger', cache_timeout=0), name='schema-swagger-ui'),
  path('redoc/', schema_view.with_ui('redoc', cache_timeout=0), name='schema-redoc'),
  ```
- **Преимущества использования yasg**:  
  Автоматическая генерация документации облегчает поддержку API, позволяет интерактивно тестировать эндпоинты и предоставляет актуальную информацию для разработчиков и клиентов.

yasg интегрирован таким образом, чтобы изменения в API автоматически отражались в документации без дополнительного вмешательства, что повышает прозрачность и удобство работы с API.

## 4. Кратко о asgi.py и wsgi.py

Хотя файлы asgi.py и wsgi.py обычно не требуют частых изменений, их назначение таково:

- **wsgi.py**:  
  Это точка входа для WSGI-серверов в продакшене (например, Gunicorn). Он импортирует настройки проекта и обеспечивает обработку синхронных HTTP-запросов. Если вы не вносили изменения, файл остаётся стандартным.

- **asgi.py**:  
  Это точка входа для ASGI-серверов, предназначенная для поддержки асинхронных запросов и протокола WebSocket. Для современных проектов, требующих асинхронной обработки, asgi.py предоставляет дополнительный функционал. При отсутствии изменений он также остается стандартным и не требует доработок.

# Приложения проекта

## Приложение products

Приложение Products отвечает за управление всеми данными, связанными с товарами в системе. Оно реализует полный жизненный цикл работы с товаром – от его создания до обновления и удаления. Ниже представлено подробное описание реализации приложения.

---

### models.py

В приложении products всего 2 основных модели - **Product** и **Category**

Модель **Category**:
name: Название категории (обязательное, уникальное поле)
slug: URL-friendly версия названия (уникальное поле, может быть пустым, автоматически генерируется)
description: Описание категории (необязательное поле)
Метод str возвращает название категории для отображения

Модель **Product**:
category: Внешний ключ на модель Category (PROTECT запрещает удаление категории, если есть связанные товары)
name: Название товара (обязательное поле)
description: Описание товара (необязательное поле)
price: Цена товара (десятичное число с валидатором для неотрицательных значений)
stock: Количество товара на складе (целое положительное число)
image: Изображение товара (необязательное поле)
created_at: Дата создания (заполняется автоматически)
updated_at: Дата обновления (обновляется автоматически)
Свойство in_stock проверяет наличие товара на складе
Метод str возвращает название товара для отображения

Модели связаны отношением один-ко-многим: одна категория может содержать множество товаров (related_name='products' позволяет получить все товары категории через category.products).

# Запуск проекта и тестирование

- **Запуск сервера**:  
  Для запуска сервера используйте стандартную команду Django:

  ```
  python manage.py runserver
  ```

- **Запуск тестов**:  
  Для проверки работоспособности всех модулей:

  ```
  python manage.py test
  ```
